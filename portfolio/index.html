BLOCKLY: TRANSPILADOR VISUAL Y MOTOR DE SIMULACIÓN

Este proyecto es un entorno de ejecución donde el código generado por bloques no se interpreta en caliente, sino que pasa por un proceso de pre-computación. El objetivo fue separar la intención del usuario (el bloque) del renderizado final, manejando la lógica del juego como un flujo de estados predecibles.

Decisiones de implementación:

Shadow Execution: En lugar de mover el avión en tiempo real mientras se evalúa el código, implementé un motor que genera una moveQueue. Esta cola de movimientos permite validar colisiones y límites del mapa antes de que empiece la animación, asegurando que el estado visual esté siempre sincronizado con la lógica interna.

Gestión de colisiones por proximidad: Para evitar los errores de precisión del punto flotante en JavaScript, desarrollé una función de tolerancia (isSameTile). Esto garantiza que el contacto con obstáculos se detecte de forma consistente sin depender de coordenadas exactas al píxel.

Feedback de UI por topología de bloques: Configuré listeners en el workspace para analizar la conexión de los bloques. El sistema detecta "nodos huérfanos" (bloques sin padre ejecutable) y aplica transformaciones de opacidad en el DOM de Blockly, eliminando ruido visual y errores de ejecución silenciosos.

Arquitectura de estados en React: Utilicé una estructura desacoplada donde Blockly solo actúa como el emisor de lógica, el motor físico procesa los datos y React se limita a reflejar esos cambios de posición, manteniendo el componente de vista liviano y eficiente.

URL: https://blockly-game-mocha.vercel.app/ Github: https://github.com/GomezLeandro/blocklyGame
